# Запуск и проверка

## Подготовка окружения

1. Проверь версии `node --version` и `npm --version`. Корневой `package.json` не задаёт `engines`; запись `node_modules/@strapi/strapi` в lockfile для версии 5.56.0 задаёт Node.js `>=20.0.0 <=26.x.x`. Для локальной проверки обновления используется Node.js 22.20.0; для серверного процесса также подготовлен Node.js 22.20.0 в NVM пользователя `zinc-server`. Не меняй глобальный Node.js без необходимости.
2. Если задача требует установки зависимостей, используй `npm ci` с текущим `package-lock.json`. Установка запускает lifecycle-скрипты зависимостей; после неё проверь рабочее дерево.
3. Подготовь локальный `.env` по [.env.example](../../.env.example), замени шаблонные секреты и добавь параметры выделенной PostgreSQL из таблицы ниже. Не используй рабочую или продакшен-базу для экспериментов со схемой.
4. До запуска проверь доступность выбранной БД и каталога загрузок. SQLite в `config/database.js` закомментирован; автоматически доступной локальной базы нет.

### Переменные окружения

| Переменная | Где используется | Что учитывать |
| --- | --- | --- |
| `HOST`, `PORT` | `config/server.js` | В примере `0.0.0.0:1337`; для локального запуска без доступа из сети используй `HOST=127.0.0.1` |
| `APP_KEYS` | `config/server.js` | Массив ключей через `env.array`; значения примера нужно заменить |
| `ADMIN_JWT_SECRET`, `API_TOKEN_SALT` | `config/admin.js` | Секреты админки и API-токенов; значения примера нужно заменить |
| `JWT_SECRET` | Объявлен в `.env.example` | В пользовательских файлах `config/` напрямую не читается; назначение в Users & Permissions проверяй по установленному плагину |
| `DATABASE_HOST` | `config/database.js` | По умолчанию пустая строка; задай адрес локальной PostgreSQL явно |
| `DATABASE_PORT` | `config/database.js` | По умолчанию `5432` |
| `DATABASE_NAME` | `config/database.js` | По умолчанию `postgres`; задай отдельную базу проекта |
| `DATABASE_USERNAME` | `config/database.js` | По умолчанию `postgres`; используй локального пользователя с нужными правами |
| `DATABASE_PASSWORD` | `config/database.js` | По умолчанию пустая строка |
| `DATABASE_SSL` | `config/database.js` | Читается через `env.bool`, по умолчанию `false`; значение зависит от целевой БД |

Все `DATABASE_*` из таблицы отсутствуют в текущем `.env.example`. Пример сам по себе не является полной настройкой запуска.

## Локальное окружение обновления

Текущий корневой `.env` указывает на рабочую базу Supabase. Для локального запуска используй выделенную PostgreSQL в Docker на `127.0.0.1:55432` и файл `.tmp/local-runtime.env`. Приложение слушает `127.0.0.1:3001`; проверка миграции выполнялась на отдельной копии базы на порту `3002`.

```sh
set -a
source .tmp/local-runtime.env
set +a
export PATH=/Users/sonyblack/.nvm/versions/node/v22.20.0/bin:$PATH
export ENV_PATH=$PWD/.tmp/local-runtime.env
npm run dev
```

Локальные env-файлы и дампы содержат секреты или данные; они находятся в игнорируемом `.tmp/` и не входят в Git.

## Команды

Источником команд служит [package.json](../../package.json). В текущем README указан `npm run develop`, но такого npm script нет.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | `strapi develop`: разработка с автоперезагрузкой; требуется настроенное окружение |
| `npm run build` | `strapi build`: сборка админки; не доказывает подключение к БД или работу API |
| `npm run start` | `strapi start`: запуск без автоперезагрузки |
| `npm run strapi -- --help` | Справка CLI установленной версии; проверь нужную команду и флаги перед генерацией или другими операциями |

Зависимости React не означают наличие отдельной команды запуска клиентского сайта. Пользовательского фронтенда в этом репозитории нет.

## Особенности обновления Strapi 5.56.0

Jodit Editor 1.1.5 использует `useIntl().formatMessage`. Его peer-зависимость `react-intl` закреплена через npm `overrides` на `6.6.2`, которую использует Strapi; сборка и сохранение HTML проверены на копии базы. Не устанавливай зависимости с `--force` или `--legacy-peer-deps`.

На сервере сборку запускай от `zinc-server` с Node.js 22.20.0 и `SWC_NATIVE_BINDING_CACHE=/var/cache/zinc-server-swc`. Каталог кэша принадлежит `zinc-server` и имеет права `700`; стандартный кэш внутри домашнего каталога не проходит проверку SWC из-за групповой записи в родительский каталог.

## Выбор проверки

В репозитории нет тестов, настроенного CI и npm scripts `test`, `lint`, `typecheck`. `.eslintrc` ссылается на `babel-eslint`, но ни `eslint`, ни `babel-eslint` не объявлены в зависимостях и не представлены в lockfile. Не запускай `npx` с автоматической установкой инструментов ради проверки и не добавляй их в документационную задачу.

| Изменение | Минимальная проверка |
| --- | --- |
| Документация | Сверить факты, команды и ссылки с кодом; проверить diff и форматирование. Сборка приложения не требуется |
| Серверный CommonJS JavaScript | `node --check <изменённый-файл.js>`; затем воспроизвести затронутый сценарий на локальном сервере |
| JSON-схема | Проверить JSON-парсинг, UID ссылок, парные отношения и допустимые компоненты; затем запустить Strapi на изолированной БД и проверить модель и API |
| Контроллер, сервис, маршрут или доступ | На локальном сервере проверить успешный запрос, ошибочный ввод и запрос с недостаточными правами; для публикуемых типов проверить нужные состояния публикации |
| Схемы и генерируемые типы | Сверить генерацию с исходными схемами и просмотреть diff; выбрать команду генерации по CLI help установленной версии |
| Админка, Jodit, CSP или upload | Выполнить `npm run build`, затем проверить соответствующий экран в Google Chrome; для upload проверить допустимый тип файла и его доступность после загрузки |

`node --check` выше относится к серверным CommonJS-файлам. `src/admin/app.example.js` и `.strapi/client/app.js` содержат ESM; их синтаксис обрабатывает сборщик админки, а не CommonJS-проверка.

После сборки или запуска отдельно просмотри изменения в `types/generated/` и `.strapi/client/`. Не включай несвязанные результаты генерации в задачу и не удаляй их широким `git reset`/`git clean`.

## Границы подтверждения

При первичном изучении проекта 2026-10-03 в рабочем дереве не было `node_modules` и `.env`; приложение, PostgreSQL, админка и права ролей не проверялись в работе. Документы основаны на исходниках и lockfile. Перед задачей, требующей выполнения приложения, заново проверь окружение; этот снимок не описывает текущую доступность сервисов.

В отчёте перечисляй выполненные команды и сценарии, а также то, что осталось непроверенным. Статический разбор, JSON-парсинг и успешная сборка не заменяют проверку API, данных, прав или UI.
